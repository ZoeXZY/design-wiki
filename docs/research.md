# 研究思路与当前证据

项目面向设计规范的使用与维护，核心问题是：当前条件下什么规则适用，已有事实是否支持结论，依据变化后哪些记录需要复核。

## 四项设计判断

1. 把版本、对象、级别、单位和例外纳入知识结构。
2. 分开记录适用性、满足情况、条款关系和复核状态。
3. 缺失可能改变结论的信息时保留未知，同时说明缺什么。
4. 保存依据与结论的依赖，变更后只提示相关记录复核，保留旧快照。

它们通过可运行机制接受检验，目前没有独立用户研究证明各原则能提高多少效率。

## 方法演进

早期对照用同一语料、同一问题比较800字符/120重叠固定窗口、条款边界以及显式来源范围过滤，共享字符3-gram TF-IDF、余弦排序和Top-K=3。24问题×3条件加16结构化案例构成88条正式模型任务，使用相同模型与生成条件；完整回答并不等于正确回答。

一个错误是片段留下变更说明却丢失同一项日期，回答将下一项日期错配。当前程序保留完整日期记录。另一个问题是跨体系比较缺少一方资料，当前支持显式多来源及分别取候选。当前已换成BM25与Top-K=4，这些调整不能被写成单变量对照的因果收益。

当前实现用JSON概念关系、规则执行、状态门槛与依赖追踪。它不使用Embedding、模型微调、通用图数据库或本体推理引擎。自然语言问答与确定性规则判断分别记录。

## 可复现的维护示例

构造一个24×24 CSS px目标，明确所有相关例外均不成立。先保存原判断，再经候选、审核和影响预览，将本地尺寸阈值改成30×30，发布后复核。旧pass保留，新fail关联旧记录。30×30是构造的本地政策，不是W3C官方修订；例外未明时应保留unknown。

## 下一步

先人工复核参考标签，建立未见测试集，固定模型与检索条件分别检查日期保全、双来源覆盖、元数据过滤；再请设计者完成查找、判断和更新任务，记录误用、复核数量与实际耗时。
